# Пайплайны документации VitePress

## Контекст

Документация проектов переехала на VitePress. Английские страницы находятся в `docs/**/*.md`, русские переводы — в `docs/ru/**/*.md`. Текущие pipeline ожидают HTML в `docs/en/` и `docs/ru/` и добавляют собственный HTML-шаблон.

## Цель

Перевести генерацию и перевод документации на Markdown для VitePress, сохранив зеркальное соответствие исходному коду и не обрабатывая русские страницы как английские.

## Детали реализации

- `src/<path>.ts` соответствует `docs/src/<path>.md`.
- Генератор сканирует Markdown внутри `docs/`, исключая `docs/ru/` и скрытую конфигурацию `.vitepress/`.
- Генератор не создаёт исходный код из VitePress-страниц, не сопоставленных исходникам (например, `docs/index.md` или руководств).
- Переводчик сканирует те же английские документы и пишет зеркальные файлы в `docs/ru/`.
- Удалить HTML-нормализацию и оборачивание в `DOC_TEMPLATE` из выполнения обоих pipeline.
- В промптах требовать валидный VitePress Markdown, сохранять YAML frontmatter, Markdown, Vue/VitePress компоненты, code fences и код; переводить человекочитаемый текст, локализовать внутренние ссылки по правилам VitePress проекта и сохранять внешние URL/якоря.
- Источник документации для E2E-планирования также переключить на английские страницы `docs/**/*.md`, исключая `docs/ru/`.
- Все агентские вызовы используют `model: 'code-check-model'`.
- Обновить связанные тесты и README.

## Критерии приёмки

- [x] Английская генерация не сканирует `docs/ru/` и не генерирует код из страниц без соответствующего исходника.
- [x] `src/example.ts` сопоставляется с `docs/src/example.md`, перевод — с `docs/ru/src/example.md`.
- [x] Генератор и переводчик не создают HTML-обёртки и сохраняют VitePress frontmatter/синтаксис.
- [x] E2E-планирование читает Markdown из английской части VitePress docs.
- [x] `pnpm check` и `pnpm test` проходят: 28 тестов.
