# Команда обновления code-check

## Контекст

Локальный CLI содержит команду `update`, но опубликованная `@human-horizon/code-check@0.4.2` её не содержит. Команда `npx code-check update` разрешает посторонний unscoped-пакет `code-check@1.0.7`, а не пакет Human Horizon. В проекте `warp` при этом остаются старые ненумерованные pipeline-файлы.

## Цель

Опубликовать версию `@human-horizon/code-check`, содержащую команду `update`, и документировать scoped-вызов CLI. Команда обновляет пакет до `latest` в `.lore/weft`, удаляет старые pipeline-файлы и устанавливает семь нумерованных entry-файлов.

## Детали реализации

- Использовать существующее определение менеджера пакетов: pnpm при наличии `pnpm-lock.yaml`, иначе npm.
- Для pnpm сохранить `--config.minimumReleaseAge=0`.
- Обновлять пакет с явным `@latest`.
- После обновления копировать pipeline entry-файлы из установленного пакета и удалять старые имена `check-*.ts` и ненумерованные `generate-*.ts`.
- Сохранять текущий порядок имён `01-` … `07-`.
- Документировать `npx --yes @human-horizon/code-check@latest update [project-path]`; не использовать unscoped `npx code-check`.
- Исправить устаревший экспорт `./dead-code-check`, чтобы он ссылался на существующую реализацию `problem-check`.
- Поднять версию, собрать пакет и опубликовать новую версию.
